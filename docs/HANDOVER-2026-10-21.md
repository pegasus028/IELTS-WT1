## 2. The outstanding items

Ordered by value to students. Each has the file, the symptom, the fix the walkthrough recommended, and the acceptance check. Items 1–4 are a morning's work together; 5–9 are small; 10 is an art run.

### 1. Outbox lost on a slow or refused save — `api.js`
- Where: `sendSave()` (~line 270) drops the outbox rows it sent only when `r.ok`; good. But `flushBeacon()` (~line 402) calls `setOutbox([])` as soon as `navigator.sendBeacon` returns true — the beacon can still be refused by the server (stale rev, lockout) or time out, and those attempts are gone. A `call('save')` that times out also leaves `saving` resolved with `{ok:false}` and nothing retries until the next user action.
- Fix: (a) in `flushBeacon`, keep the rows in the outbox and mark them `beaconed:<ts>`; on the next `sendSave` include rows not yet acknowledged (the server already ignores duplicate attempt rows by `ts+studentId+itemId` — add that dedupe in `Code.gs` `saveAttempts` if it is not there, see item 2); (b) on `{ok:false}` from a timeout, schedule one retry after 15 s (the report queue `flushReports` already does this pattern — copy it).
- Accept: `node tools/save-order-test.js` extended with a case "beacon accepted by browser, server refuses → rows still in outbox and sent by the next save"; smoke passes; no duplicate Attempts rows after two saves of the same outbox.

### 2. Duplicate Attempts rows — `Code.gs` ~line 228 (`saveAttempts`) + the Sheet
- Symptom: a few duplicated rows for B2 (m08s2) and A1/A2 gates from overlapping saves before the P1 fix. Harmless to the Staff Room (it keeps the best), but item 1 makes an idempotent write necessary anyway.
- Fix: in `saveAttempts`, skip a row whose `ts + studentId + itemId + given` already exists in the last N rows for that student (use a CacheService set of recent keys to keep it O(1)); add a `gs-test.js` case. Clean-up of the existing duplicates is T.Chris's call (a one-off `dedupeAttempts()` function in Code.gs he can run from the editor is the safest offer).
- Accept: `node tools/gs-test.js` green with the new case.

### 3. COMPARE frames can leave a category unmentioned — `lab-content.js` ~lines 222–280, `template.js`, `writer.js` coverage ward ~line 218

Details: `tools/walkthrough/live/good-examples-for-app.json` → `excluded`, and EXAMPLE-BANK.md §4.
- Fix: (a) Workshop Design check for COMPARE: every category label of the Test-Drive chart must be reachable from the page's slots (count `[Group A]/[Group B]/[Largest]/[Smallest]`-type slots against `p.labels`); warn "This page names at most N of the M categories — add a slot or a 'the remaining …' line". (b) Cast data check for degree words: if a frame carries a built-in claim word (by far, closely, similarly, barely, only), check it against the filled figures (ratio thresholds: "by far" ≥ 1.5×, "closely/similar" within 15 %, "barely/only" ≤ 0.5× of the next) and mark ≈ with the note "The frame's claim word does not fit these figures — reword or drop it". Put the word list in `template.js` next to the approximation rules so `lab-check-test.js` covers it.
- Accept: new cases in `lab-check-test.js` (the three C1 lines above must come out ≈/✗ on the screen-time chart) and `lab-validate.js`; the coverage ward on a report built from an approved COMPARE page is never red for a category the page could not name.
